    How it works
    
      
    Pick a game. Pick an agent. Watch.
    
    
    
    
      
      
    1. 01
      Open your game
      Drop in a game for N64, PlayStation 1 or 2, GameCube, Wii, Game Boy Advance or DS, as a ROM, disc image or program file. decomp.wtf finds every function. GameCube, Wii and N64 are the recommended platforms, the most tested path to a full decomp you can port and mod; the rest are in beta. Or continue a public decomp for any platform. Your file never leaves your computer.
      2. 
      
    2. 02
      Add your agent
      Claude Code, Codex, Antigravity CLI, opencode, or any model with an API key. Run several at once: each takes a different function, and they share what they learn.
      3. 
      
    3. 03
      Watch it match
      The map fills in as functions match. Every attempt, score and name is live. Export the source whenever you like, or decompile it as a team: everyone with their own copy and their own agents.
      4.

    The rule
    
      
    Score 0, or it doesn't count.
    
      
      
        
    • Byte-identical, not "close". Each attempt is built with the game's own compiler and compared with the original.
      • 
        
    • Every miss explains itself. The agent gets an instruction diff and fixes structure first, registers last.
      • 
        
    • Knowledge compounds. Structs, prototypes and names are shared, and only accepted if everything matched so far still matches.
      • 
        
    • Finished means linked. On GameCube and Wii, a file that matches completely is built into the game, and the whole game must still match its checksum.

    Bring the agent you already use.
    
      
    decomp.wtf is free. Your agent runs on your own subscription or API credits; the app installs it if you don't have it yet and tells you how to sign in.

    Agents only get decomp.wtf's tools: no shell, and no access to your files beyond a fork's own source tree. They also get the know-how decomp veterans use: the game's compiler, machine-made drafts (m2c, Ghidra), a look-alike finder that starts them from code that already matches, a data inspector, a call graph, and guides for MIPS, PowerPC, ARM, x86, AArch64, Metrowerks, GCC, IDO, C++ and objdiff.

    FAQ
    Good to know
    
    
    
      
    Why "decomp.wtf"?
    WTF stands for What The Function: what everyone says the first time they stare at a page of MIPS assembly. decomp.wtf answers it, one function at a time.
    
      
    Why not just ask a general AI agent to decompile my game?
    You can, and with decomp.wtf connected that's exactly what happens, minus the hours of setup. Matching decompilation needs the game's original compiler at the right version and flags, a splitter that finds every function, a judge that compiles each attempt and compares it with the game byte for byte, and a way to keep many agents from colliding. decomp.wtf brings all of that, pinned and ready in seconds, plus free matches before your agent spends a token (code the game has more than once, machine drafts, a permuter for near misses), a live view, and an export that rebuilds the game.
    
      
    Which games work?
    From scratch: Nintendo 64 (KMC GCC, IDO), PlayStation and PlayStation 2 (PSY-Q GCC, EE-GCC), GameCube and Wii (CodeWarrior, as a dtk-template project), Game Boy Advance (agbcc) and DS (CodeWarrior for DS, as a ds-decomp project). PC, Switch and more are coming. Beyond that, any public decomp whose build produces an objdiff report, which covers practically every project on decomp.dev, on every platform.
    
      
    Which computers does it run on?
    Linux, and Windows (supported, still unstable). Several of the compilers only exist as Linux programs, so on Windows decomp.wtf runs in its own small Linux (WSL 2), which the installer sets up. You use it in your browser either way, and the results are byte for byte the same. macOS isn't supported.
    
      
    C or C++?
    Both. GameCube, Wii and DS games are often C++, and decomp.wtf handles it: code with C++ symbol names goes into .cpp files, drafts come out as C++, and agents get a guide to classes, vtables, constructors and name mangling. N64, PlayStation, PS2 and GBA games started from scratch are written in C for now; C++ there (mostly PS2) is coming. Public decomps use whatever language the project uses.
    
      
    Can we decompile a game as a team?
    Yes, as many people as you like, each on their own computer with their own copy of the game and their own agents. One of you hosts the room on a home PC or a server (decomp host), public or private, and decides who's in. Functions are handed out so nobody collides, every match is checked against the host's copy, and names, structs and notes are shared. Nothing goes through decomp.wtf: you host it, and you decide who sees the code.
    
      
    Can I use the result for a port or a mod?
    That's the idea. Export project writes a normal decompilation project, matched functions as C and the rest as assembly, that rebuilds your game byte for byte (GameCube, Wii and DS projects do that on every build). On GameCube and Wii, finished files are linked as you go: the game is built from their C, the way decomp.dev projects count "linked", which is what a native PC port starts from. Keep going with any tool or agent until it's all C. Game code and data stay out of git and are regenerated from your own copy.
    
      
    Will my agents' code end up in the community's project?
    Not by itself. In a public decomp, every match is a commit on your own local branch and nothing is sent anywhere. Many projects don't accept AI-written contributions, and the ones that do expect a person to stand behind every line: read the project's contribution rules, review the code yourself and say how it was made before you open a pull request.
    
      
    Do I need to know anything about decompilation?
    No. The agent does the work and the app shows what's going on. If you read MIPS, you can follow every attempt and jump in.
    
      
    What does it cost?
    Nothing; the app is free and open source (MIT, source on GitHub). Your agent uses your own plan or API credits. In our tests a small function cost Claude Code about 8 cents, DeepSeek a fraction of that, and a local model nothing at all. Big functions take many more attempts, and cheaper models often get stuck on them, so the easy part of a game goes fast and the rest takes real time.
    
      
    Is it legal?
    decomp.wtf is a tool, like a disassembler: it contains no game code and runs on your computer. How you use it is up to you and the law where you live. Use games you own and keep the results private. This isn't legal advice.
    
      
    What does it build on?
    splat and spimdisasm split ROMs, objdiff judges forks, m2c and Ghidra write first drafts, the decomp community's recompiled period compilers do the building, and decomp.dev lists the public projects. Not affiliated with any of these projects.
